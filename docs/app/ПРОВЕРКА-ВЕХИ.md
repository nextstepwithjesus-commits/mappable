# Проверка вехи (В-20)

Быстрая проверка после каждой вехи: не разошлась ли сделанная работа с главными требованиями проекта. Это не рецензия: цель — заметить грубое расхождение рано, пока исправление дёшево, а не когда половина продукта готова. Делает агент `milestone-checker` или, если заняты четыре агента, сам координатор по этому списку. Итог — строка в журнале: «проверка вехи: соответствует / замечания: …».

Веха — решение владельца, новая редакция или черновик документа, принятая рецензия, этап данных, исследование, прототип, новое правило или инструмент.

## Чек-лист (каждый пункт — «да / нет / не касается»)

**А. Обязательные решения владельца** (`npm run -s find -- ОБЯЗАТЕЛЬНО`)
1. Карточка есть у каждого действующего лица Библии — ничего в работе этому не мешает (В-10).
2. Интерфейс продукта не реализуется до утверждения документов по инструменту.
3. Одновременно не больше четырёх агентов.
4. Главный вход — каталог всех историй; страница истории с лицами, текстом, всеми местами Писания и переходами в инструменты (В-19).
5. Планка качества: решения опираются на изученные материалы, научные труды и лучшие образцы; облик — профессиональный (В-19).

**Б. Правда**
6. Каждый факт — со стихом из 66 книг; нет предания и внебиблейских сведений под видом Писания.
7. Скобки — не основание (02 § 3.8); толкование не стало фактом (R9, Г-5).
8. Простой слой не выдаёт подпись атласа, картинку или расчёт за слова Библии.

**В. Процесс**
9. Документ прошёл свой порядок (регламент § 6): исследование → черновик → панель из 4+ рецензентов → исправление → владелец.
10. Работа не опирается на неутверждённый документ, кроме мест, помеченных «предварительно».
11. Правки данных — шагами с областью и вторым ключом.
12. Прототип для владельца — по дизайн-системе либо назван «серый макет».

**Г. Согласованность — риск большой переделки**
13. Не противоречит утверждённой концепции (01), данным (02) и решениям В-N; если противоречит — отступление записано и вынесено владельцу.
14. Не противоречит соседним документам (одно понятие — одно имя и одно правило во всех документах: например, «События» = каталог историй на шкале).
15. Модель данных умеет то, что требует работа (`tools/base/types.ts`); если нет — записана задача данных.
16. Учтены ребёнок 6–7 лет и учёный, телефон и доступность, работа без сети.
17. Числа взяты скриптом из данных, а не на глаз.

**Д. Учёт**
18. Строка в журнале; раздел «Сейчас» в карте обновлён; вопросы владельцу собраны.
19. Задачи и спорные места — в очереди; сделанное помечено.
20. Всё закоммичено и отправлено; `npm run -s docs:check` — ноль ошибок.

## Формат отчёта (не длиннее 15 строк)

```
Веха: <что проверено, коммит или файлы>
Итог: соответствует / есть замечания / грубое расхождение
Замечания (не больше 7, самые важные):
- [грубо | внимание] что не так — где (файл:строка) — какое требование (пункт чек-листа, В-N)
Что проверено: <пункты, которые прошли>
```

Решение, что и как исправлять, принимает координатор: правит сам, запускает агентов или записывает с причиной.
