# Рецензия данных и производительности на 02 «Данные», ред. 4.3

**Статус:** рецензия инженера данных и производительности, 11 октября 2026. Проверялась поправка 4.3 (коммит c217ac5; `git diff b87f61d c217ac5 -- docs/app/02-ДАННЫЕ.md`) по разбору `reviews/Д-р10-разбор.md`: § 3.3.4 (виды а/б/в), § 3.3.5 (уровень у формы имени), § 3.3.6 (показ), задачи К-18, Д-15. Документы и данные не правились, ничего не закоммичено.

**Как проверял.** Читал `tools/base/types.ts` (`Name`, `Assertion`, `Origin.identity`, `EndIdentity`, `Redirect`, `StoryActor`), `validate.ts` (строки 170–184, 290–335), `admit.ts` (`recordVerses`, `inputsOf`, подписи), `bundle.ts` (`buildIndex`, `citedRefs`, пакеты стихов). Числа — скриптами в scratchpad (`python3 -I`) по `base/actors/*.json`, `base/origins.json`, `kin.json`, `unions.json`, `memberships.json`, `checks.json`, `relations.json`, `stories.json`. Объём индекса — по `dist-data-probe/index.json` и его `manifest.json`. Цитаты — `python3 -I docs/app/data/07-цитаты.py docs/app/02-ДАННЫЕ.md`: 142, не найдено 0.

**Образцы.** Wikidata (свойство «также известен как» с квалификатором источника и ранга — у каждого другого имени своя ссылка и своя степень); TIPNR STEPBible (у каждого имени — свои стихи, а слитые лица помечены отдельно); Encyclopedia of the Bible и Wikipedia (Uzziah: «also known as Azariah» — одна статья с пометкой). Правило 4.3 по смыслу совпадает с ними. Но в модели и в сборке его пока нельзя ни записать целиком, ни проверить.

## Что подтвердилось

- Четыре ребра вида (б), которые держатся только на другой форме, скрипт нашёл те же: `o-iofor--khovav`, `o-rekhum-neem12--adna-neem12`, `o-meremof-neem12--khelkiya-neem12-15`, `o-akhamani--isbosef`. Для всех 54 форм — 9 рёбер, как в Д-р10 § 4.2.
- 40 форм вида (б) все есть в данных, на 38 карточках. Ни одна из этих карточек не подписана (0 из 38; для всех 54 форм — 0 из 50). Новые поля у этих форм подписей не снимут.
- У всех лиц первая форма в `names` — вида `main`: правило «форма „выв.“ не бывает основной» сейчас ничего не ломает.
- Сборка уже отличает „предположительно“ (`isCand` в `bundle.ts`: `identity.degree === 'possible'`). Значит, ребро со степенью `inferred` будет нарисовано, а не уйдёт в список кандидатов. Это верно.
- Бюджет индекса не под угрозой. Сейчас индекс — 104,4 КБ в gzip при бюджете 200 КБ. Пометка уровня у 44 форм и 12 новых карточек добавляют, по моей пробе, около 0,2 КБ.

- **Индекс.** Сейчас 104,4 КБ gzip из 200 КБ (`dist-data-probe/manifest.json`). Поправка добавит около 0,2 КБ (проба по `index.json`). Мерить, как сейчас: `npm run -s base:bundle`, поле `budget.indexGzip`. Других бюджетов поправка не задевает.

## Какие проверки и тесты нужны (К-18 и задача сборки)

1. Форма `inference`: `compare` со стихами обеих сторон. В `compare` есть хотя бы один стих этой формы и хотя бы один стих формы „Писание“ той же карточки. Просто „не меньше двух стихов“ этого не гарантирует. Есть `why`.
2. Ровно одна форма `type: 'main'`, она `scripture`.
3. Переадресация лица — с видом основания (`basis: 'said' | 'parallel'`). При `said` обе формы стоят в одном стихе вне скобок (Мф 10:3). При `parallel` у карточки-цели есть форма `inference` со стихами карточки, которая уходит. Сейчас проверка смотрит только, есть ли у переадресации стихи (validate.ts, строка 345).
4. Форма без общего стиха с формой „Писание“ — `inference` или в подписанном списке написаний (№ 3).
5. Тождество по форме: `form` есть у карточки-конца и она `inference`. Стихи ребра — стихи этой формы (№ 11).
6. `compare` входит в отпечаток подписи, в проверку стихов и в пакет стихов (№ 2).
7. Индекс: формы „выв.“ помечены. Выдача ставит совпадение с формой „Писание“ выше (№ 8).
8. Фаддей: тесты из № 7 — переписаны, не сняты.
