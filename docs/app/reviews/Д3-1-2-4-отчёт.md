### 1.1. Допуск (Д3-1)

- **Действующий статус** берётся по порядку: статус самой записи → статус содержащей записи (у утверждения — статус лица) → статус файла → «черновик».
- **«Проверено»** ставится только по подписи с совпавшим отпечатком. Статус «проверено», записанный без подписи, считается черновиком, а валидатор даёт ошибку.
- **Уровень «выпуск»** (`release`) допускает только «проверено». **Уровень «проба»** (`probe`) допускает и черновики. Карантин не допускается никогда.
- **Зависимости:**
  - утверждение, «нет сведений» и время допускаются только вместе с допущенным лицом;
  - ребро происхождения и родство словами — при обоих допущенных концах и допущенном наборе прочтений;
  - союз — при обоих допущенных супругах;
  - членство — при допущенных лице и области;
  - область — при допущенных основателе и области-родителе;
  - линия — только целиком: каждое лицо и каждый набор прочтений должны быть допущены;
  - переадресация — при каждой допущенной цели.
- **Части записи** — обозначения союза и имена лица — идут вместе с записью. Отдельно они выпадают только при явном карантине.
- **Отметку пробы нельзя убрать.** В каждом файле сборки (индекс, карточки, стихи, опись) есть `admit`. У пробы рядом стоит `banner: "Данные не проверены: проба"`. Проба пишется только в `dist-data-probe/`, выпуск — только в `dist-data/`. Если перепутать папки, сборка остановится с ошибкой (`assertOut`).
- **Опись** (`manifest.json`, схема 2) пишет:
  - уровень допуска;
  - числа по статусам для каждой коллекции;
  - sha256 `brackets.tsv`, `source-issues.tsv`, `base/sources.json`, `base/checks.json`;
  - отпечаток всех файлов `base/` (не только коммит).

### 1.2. Отпечаток и подпись (Д3-2)

- **Ключи записей устойчивы:** `actor:p-avraam`, `fact:p-avraam|17|events` (повтор — `#2`, `#3`), `origin:p-isaak|p-avraam|father|p`, `union:u-avraam--sarra`, `kin:…`, `membership:…`, `nodata:…`, `reading:…`, `area:…`, `line:luke`, `redirect:…`, `chrono:…`, `epoch:…`.
- **Отпечаток** — sha256 канонического JSON из трёх частей: вид записи; запись без `prov` на любой глубине (у лица — ещё и без утверждений, у них свои подписи); входы. Входы — список стихов записи, sha256 их текста, sha256 строк `brackets.tsv` и `source-issues.tsv` об этих стихах и `{номер источника: версия}`. В источники входит `src-synodal` и каждый `src-…` из полей `source` и `sources` записи.
- **Подпись** хранит, кто проверил, человек это или агент, когда, отпечаток и входы. Повторная подпись переносит прежнюю в `history`.
- **Что снимает статус.** Любая правка записи или её входа возвращает запись в «черновик». Валидатор тогда даёт ошибку и называет причину: «изменилось содержимое записи», «изменился текст её стихов», «изменились строки brackets.tsv о её стихах», «изменились строки source-issues.tsv о её стихах», «источник X: старая версия → новая». Ошибкой считаются ещё четыре случая: подпись записи, которой больше нет; подпись записи в карантине; «проверено» без подписи; подпись без «кто», «когда» или «человек или агент».

### 1.3. Исправление по рецензии 09, № 1

- **Было:** во входы подписи шли sha256 целых `synodal.tsv` и `brackets.tsv`. Правка одной строки скобок сняла бы «проверено» со всей базы; `source-issues.tsv` во входы не шёл.
- **Стало:** отпечаток = запись без `prov` + список её стихов и sha256 их текста + sha256 строк `brackets.tsv` и `source-issues.tsv`, которые задевают эти стихи + версии её источников. Стихи берутся из полей `refs`, `ref`, `first`, `key`, `all`, `verse`; ссылка на главу — все стихи главы.
- **Проверено тестами:** правка чужого стиха или чужой строки таблиц подпись не снимает; правка своего стиха, своей строки скобок или своего дефекта — снимает и называет причину.
- Целые файлы остались только в описи выпуска (`manifest.json`, § 5.4).

## 2. Как пользоваться

| Команда | Что делает |
|---|---|
| `npm run -s base:validate` | Проверка базы. В конце печатает строку «записей: проверено …, черновик …, карантин …; подпись устарела …; допущено в выпуск …». |
| `npm run -s base:bundle` | Сборка уровня «выпуск» в `dist-data/`. Сейчас она почти пуста: проверенных записей нет. |
| `npm run -s base:bundle -- --probe` | Сборка уровня «проба» в `dist-data-probe/` (только для прототипов). |
| `npm run -s base:mark -- --list p-avraam` | Ключи записей, в которых есть эта подстрока, и их статус. |
| `npm run -s base:mark -- --by "имя" --kind human\|agent <ключ> …` | Второй ключ подписывает записи. |
| `npm run -s base:mark -- --by "имя" --kind agent --actor p-avraam` | Подписывает лицо, его утверждения (кроме карантина), «нет сведений» и время. |
| `npm run -s base:mark -- --stale` | Подписи, которые больше не действуют, и почему. |
| `npm run -s base:mark -- --unmark <ключ> …` | Снимает подпись. |
| `npm run -s verse -- "Пс 114:8-9"` | Стих и строка «   ! …» с пометкой из таблицы дефектов под ним. |

**Когда подписать нельзя:**

- запись в карантине;
- в базе есть ошибки проверки (устаревшие подписи не мешают);
- подписывает составитель записи: его имя совпадает с `prov.by`.

Команду `npm run -s base -- --check-mark` из задания я не делал. `base` — это перенос (`migrate.ts`): он пересобирает `base/` из `data/`, а подписи должны переживать пересборку. Поэтому подписи живут в отдельном журнале, который перенос не трогает, и у них отдельная команда `base:mark`.

**Где видны дефекты:**

- **`verse`.** Пустой стих печатается словами «(стих пуст в электронном тексте)» и с причиной. Если пустой стих не записан в таблице, `verse` предупреждает «!!».
- **`07-цитаты.py`.** Он читает ту же таблицу. У ненайденной цитаты из пустого стиха печатается причина. Цитата из стиха с дефектом получает «ПОМЕТКА» и строку причины. Пометка — не ошибка: число «не найдено» от неё не меняется. Итоговая строка дополняется словами «; пометок дефектов текста: N» только при N > 0, поэтому вывод по документам 00–11 не изменился.
- **Валидатор.** Ссылка на пустой стих, в том числе внутри диапазона, — ошибка «дефект текста» с причиной из таблицы. Сверка таблицы с файлом — тоже ошибка: каждый пустой стих должен быть в таблице, каждая строка — указывать на существующие стихи.
