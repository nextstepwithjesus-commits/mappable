# ТЗ и промт для агента GPT-6.1 Sol: «Толедот» — звёздный атлас библейских родословий

Документ из двух частей. **Часть 0** — для владельца: подготовка компьютера и запуск агента в отдельной локальной папке. **Часть 1 и приложения** — промт: их целиком вставляют в первое сообщение агенту.

Промт написан по рекомендациям OpenAI для GPT-6.1 Sol:
- модель выполняет указания буквально, поэтому каждое правило сказано один раз и правила не противоречат друг другу;
- задача описана через результат, контекст, ограничения, инструменты, свидетельства, проверку, условия остановки и итоговый результат;
- «готово» определено проверяемо;
- память и собственные инструкции агента вынесены в файлы (AGENTS.md, ExecPlan, роли, навыки Codex), а не в историю разговора.

## Часть 0. Для владельца: подготовка компьютера и запуск (в промт не вставлять)

Проект живёт на вашем компьютере, в отдельной папке `~/projects/toledot-sol`, со своей локальной историей git. Прежняя версия атласа лежит рядом, в подпапке `reference/`: агент берёт из неё данные и решения, но ничего в ней не меняет и ничего не отправляет в GitHub.

### 0.1. Программы

| Что | Зачем | Как поставить |
|---|---|---|
| WSL 2 с Ubuntu (только Windows) | Codex на Windows надёжнее всего работает внутри WSL | PowerShell от имени администратора: `wsl --install`, перезагрузка; дальше все команды — в терминале Ubuntu |
| Node.js 22 или новее | Codex и сборка атласа | nodejs.org; в WSL и Linux — через `nvm` |
| Git | история проекта | Ubuntu: `sudo apt install git`; macOS: `brew install git` |
| Python 3 | установщик навыков Codex | Ubuntu: `sudo apt install python3`; macOS: `brew install python` |
| ripgrep и jq | быстрый поиск по коду и данным | Ubuntu: `sudo apt install ripgrep jq`; macOS: `brew install ripgrep jq` |
| Codex CLI (GitHub: `openai/codex`) | сам агент | `npm install -g @openai/codex`, затем `codex login` |

Проверка: `node -v` — 22 или больше; `codex --version` — без ошибки.

### 0.2. Папка проекта

```bash
mkdir -p ~/projects/toledot-sol && cd ~/projects/toledot-sol
git init -b main
git clone --branch claude/bible-genealogy-interactive-map-9b143k --single-branch https://github.com/nextstepwithjesus-commits/mappable.git reference
mkdir -p docs && cp reference/docs/TZ-GPT-6.1-Sol.md docs/TZ.md
```

- **В WSL держите папку в домашнем каталоге Linux** (`~/projects`), а не на диске `C:` (`/mnt/c`): так сборка и тесты в разы быстрее. Из Проводника Windows папка открывается по адресу `\\wsl$\Ubuntu\home\<имя>\projects\toledot-sol`.
- **Если репозиторий закрытый**, `git clone` спросит вход в GitHub — войдите своей учётной записью.

### 0.3. Настройки Codex — `~/.codex/config.toml`

```toml
model = "gpt-6.1-sol"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true

[features]
multi_agent = true

[agents]
max_threads = 6

[mcp_servers.playwright]
command = "npx"
args = ["@playwright/mcp@latest"]

[mcp_servers.chrome-devtools]
command = "npx"
args = ["-y", "chrome-devtools-mcp@latest"]

[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]
```

Что значат строки:
- **`model`, `model_reasoning_effort`** — модель и усилие рассуждения ведущего. Если ваша версия предлагает `xhigh`, поставьте его. Распределение усилия по ролям субагентов задаёт сам промт (раздел 7).
- **`sandbox_mode = "workspace-write"`** — агент пишет только в папку проекта, но не за её пределы.
- **`network_access = true`** — разрешает ставить пакеты из npm и GitHub.
- **`approval_policy = "on-request"`** — агент работает сам и спрашивает только когда ему нужно выйти за эти рамки.
- **`multi_agent`, `max_threads`** — команда субагентов, до 6 одновременно.
- **MCP-серверы:**
  - Playwright — агент сам открывает атлас в браузере и смотрит на него;
  - Chrome DevTools — замеры скорости;
  - Context7 — актуальная документация библиотек.

Проверка: `codex mcp list` показывает три сервера. Если версия Codex не знает какой-то строки, она сообщит об этом при запуске — эту строку удалите.

### 0.6. Как следить и что делать, если агент остановился

- **Где агент сейчас** — `memory/STATE.md`; **что он решил и почему** — `memory/DECISIONS.md`; отчёты вех приходят с файлом сборки и снимками экрана.
- **Если агент остановился раньше срока**, отправьте: «Продолжай по docs/TZ.md, .agent/PLANS.md и memory/STATE.md до выполнения всех проверок раздела 10». Больше ничего объяснять не нужно.
- **Быстрый режим генерации (Ultrafast)**, если он есть, подходит исполнителям на механической работе, но не ведущему и не проверкам.
- **Модель субагентов.** Если среда позволяет её выбирать, механическую работу можно отдать GPT-6 Luna. Сверку данных, критику и итоговые проверки — только GPT-6.1 Sol.

## Часть 1. Промт

### 1. Результат

Построй «Толедот» — интерактивный звёздный атлас всех родословных связей 66 канонических книг Библии в Синодальном переводе. Результат должен быть такого уровня, чтобы ни библеист, ни картограф, ни специалист по интерфейсам и доступности не нашли в нём фактической, логической или визуальной ошибки.

Атлас должен быть понятен двум читателям сразу: человеку с учёной степенью по богословию и ребёнку шести лет.

Профессиональный уровень здесь значит:
- грамотный русский язык;
- понятный интерфейс и приятный строгий дизайн;
- понятные инструменты и фильтры;
- ясная история, хронология, связи и география;
- возможность глубоко исследовать любые связи между лицами.

Полное описание продукта — **Приложение А**. Список недостатков прежней версии, которые нужно устранить, — **Приложение Г**.

Готовый результат — четыре вещи:
- папка проекта с локальной историей git (ветка `main`);
- один HTML-файл, который работает без сервера и без сети, и его sha256;
- отчёт о проверке со снимками экрана;
- итоговый отчёт владельцу (раздел 12).

### 2. Память, инструкции и навыки — сделай это первым, до любой другой работы

История разговора — не память: её сжимают и обрезают. Твоя память и твои инструкции — файлы в папке проекта.

0. Проверь, что полный текст этого ТЗ лежит в `docs/TZ.md`. Если файла нет, запиши в него этот промт целиком.
1. Создай в корне `AGENTS.md` по шаблону **Приложения Б**. Codex читает его в начале каждой сессии. Пиши в нём только постоянные правила и точные команды.
2. Создай `.agent/PLANS.md` — живой план выполнения (ExecPlan) по шаблону **Приложения В**. Он ведётся до конца работы.
3. Создай каталог `memory/`:
   - `STATE.md` — где ты сейчас: текущая веха, что сделано (со ссылкой на свидетельство), что делается, следующий шаг, открытые вопросы. Не длиннее 80 строк; устаревшее переноси в `memory/archive/`.
   - `DECISIONS.md` — нумерованные решения: «№, дата, решение, почему, какие альтернативы отклонены, чем проверено». Решение не меняют молча: новое решение ссылается на номер прежнего.
   - `LESSONS.md` — ошибки процесса и как их не повторить.
   - `EVIDENCE.md` — журнал проверок: команда, код выхода, ключевые строки вывода, путь к снимкам.
4. Правила памяти:
   - перед каждой вехой, после каждого сжатия контекста и в начале каждой сессии перечитай `AGENTS.md`, `.agent/PLANS.md`, `memory/STATE.md` и разделы `docs/TZ.md`, нужные следующему шагу, затем продолжай с записанного следующего шага;
   - после каждого законченного шага обнови `STATE.md` и `EVIDENCE.md` и закоммить;
   - решение, принятое в разговоре, записывай в `DECISIONS.md` сразу, до продолжения работы;
   - субагенты получают нужные им сведения из этих файлов, а не из твоего пересказа.
5. **Роли.** Для каждой роли раздела 7 создай `.agent/roles/<роль>.md`: цель роли, файлы во владении, входы, обязательные проверки, формат сдачи, навыки, которые роль применяет. Это изменяемая часть брифа субагента (раздел 7).
6. **Навыки Codex.**
   - **Проектные навыки** — в `.codex/skills/<имя>/SKILL.md` по шаблону **Приложения Д**. Создай как минимум:
     - `data-volume` — составление тома по `data/AUTHORING.md`;
     - `scripture-check` — независимая сверка тома со стихами;
     - `ui-change` — правка интерфейса: снимок до, правка, снимок после, просмотр глазами, проверка § А.7.4;
     - `acceptance` — прогон `npm run gate` и разбор красного: ошибка кода или устаревший сценарий;
     - `critic-review` — порядок работы критика и важность находок;
     - `release` — однофайловая сборка, проверка без сети, sha256, итоговый отчёт.
   - **Навыки из каталога OpenAI.** Посмотри список навыков `openai/skills` через встроенный `skill-installer` и поставь те, что помогают этой работе. Playwright ставится обязательно, если владелец ещё не поставил его. Каждый установленный навык — запись в `DECISIONS.md`: зачем он нужен.
   - **Правила навыков:**
     - навык описывает порядок действий для раздела этого ТЗ и ссылается на него;
     - новых требований навык не добавляет; при расхождении действует ТЗ;
     - после каждой записи в `LESSONS.md` проверь, не нужно ли поправить навык.

### 4. Ограничения — что должно оставаться верным всегда

**Факты.**
1. Факты берутся только из 66 канонических книг Синодального перевода (1876). Исключены неканонические книги, Пс 151, Дан 3:24–90, Дан 13–14 и добавления к Есфири. Никакого предания: ни апокрифов, ни Талмуда, ни «по преданию».
2. У каждого факта — ссылка на прочитанный стих:
   - связи, возраста, места, события, имени;
   - ссылки — в синодальной нумерации и синодальных сокращениях: 1–2 Цар = 1–2 Самуила, 3–4 Цар = 1–2 Царей, псалмы — по синодальной нумерации.
3. Текст в [квадратных скобках] Синодального перевода не основание факта. Он показывается в § 24 карточки как «чтение в скобках» и питает альтернативные хронологические модели.
4. Уровни достоверности — «Писание», «выв.» (вывод), «толк.» (толкование), «расч.» (расчёт по модели). Помета стоит у каждого факта, который не сказан прямо.
5. Справочные сведения помечаются «справочно» и не выдаются за слова Писания:
   - написание в подлиннике;
   - этимология, которую не даёт сам текст;
   - координаты мест.
6. Родство, названное без родителей («братья Его», «родственница»), хранится синодальным словом дословно, без выведения родителей. Разные вероисповедные понимания перечисляются в § 24; ни одно не навязывается.
7. Годы в данных исторические: −1010 значит 1010 г. до Р. Х., нулевого года нет. Движок считает в астрономических годах и переводит только для показа.
8. Внебиблейские опоры хронологии записаны в `data/anchors.json` с источником и альтернативами. Пример: 4-й год Соломона — 967 г. до Р. Х. по Тиле.

**Язык интерфейса.**

9. Русский язык, русская типографика: «ёлочки», тире, неразрывные пробелы.
10. Имя никогда не подставляется в падеж без склонения. Либо фраза строится так, что имя стоит в именительном падеже, либо форма падежа хранится в данных.

**Дизайн** — Приложение А, § А.7.

**Запрещённые действия.**

11. Ослаблять, пропускать или удалять тесты и пороги, чтобы получить зелёный результат. Если проверка неверна, исправь её, причину запиши в текст проверки и в `DECISIONS.md`.
12. Оставлять в коде заглушки, пометки TODO, FIXME, XXX, «реализовать позже», текст-рыбу или выдуманные данные.
13. Писать «готово», «работает», «исправлено» без свидетельства из раздела 10.
14. Отмечать раздел карточки как «Писание молчит», не прочитав соответствующие стихи.
15. Редактировать `tools/bible/synodal.tsv` и что-либо в `reference/`.
16. Добавлять в сборку внешние CDN, аналитику и любые сетевые запросы.
17. Переписывать историю git (rebase, amend, force push).
18. Без подтверждения владельца выполнять разрушительные или внешние действия: удалять тома данных и файлы вне папки проекта; отправлять или публиковать что-либо за пределы компьютера, в том числе в GitHub.

## Приложение А. ТЗ продукта

### А.1. Суть

Каждое лицо — звезда. Её положение по горизонтали — время, яркость — значимость в повествовании. Роды, колена и народы — созвездия.

Две родословные линии Иисуса Христа идут через всё небо от Адама двумя лентами:
- линия по Матфею (через Иосифа) — золото к меди;
- линия по Луке — бледная лазурь к бирюзе.

Где линии совпадают, ленты сплетены; где расходятся — разведены. У каждого лица есть карточка из 24 разделов в неизменном порядке. Внизу — полоса времени от сотворения до 2040 г.

Образ взят из Писания: Быт 15:5; Пс 146:4; Откр 22:16.

### А.2. Пошаговая карта — главный вид

- **Первый экран нового читателя.** На небе два закреплённых лица: Адам и Иисус Христос. Между ними — линии Мессии свёрнутыми нитями, у каждой нити число скрытых поколений («+62» у линии Иосифа, «+74» у линии Луки).
- **Шаг вперёд** — знак «⊕» справа от имени:
  - при одном браке — супруг и все дети сразу;
  - при нескольких браках — сначала супруги, и у каждого брака ромб союза своего цвета с «+N» (щелчок раскрывает детей этого брака); следующий «⊕» — все дети;
  - надпись подсказки называет ровно то, что раскроется, словами текста по виду союза: «Жена и дети», «Жёны и наложница (4)», «Мать детей», «Все дети (13)».
- **Шаг назад** — «⊕» слева от звезды: родители, братья и сёстры. Пометы вида утверждения: «по Лк 3», «по толкованию», «предок».
- **Свёртки:**
  - «Свернуть потомков» и «Свернуть предков» у любого лица — ветвь сворачивается, остальная карта остаётся;
  - «Только это лицо» — с любого показа, в том числе со всего неба;
  - закреплённые лица остаются.
- **Журнал шагов:**
  - «Отменить шаг» (Ctrl+Z, ⌘Z) и «Вернуть шаг» (Ctrl+Shift+Z, Ctrl+Y) — по физическим клавишам, так что работают на русской раскладке;
  - «К началу» — возврат к своему началу, тоже отменяемый;
  - в полях ввода работает их собственная отмена.
- **Небо после шага:**
  - раскрытое остаётся в кадре вместе с прежним поколением;
  - справа от нового лица всегда есть место для его «⊕»;
  - путь Адам → Ной делается не больше чем за 11 действий без команды «Вписать».
- **Те же команды** — в карточке лица. Клавиши: «]» — к ребёнку, «[» — к родителю, «С» — свернуть потомков, Shift+«С» — свернуть предков.
- **Начала на выбор:**
  - «Адам и Иисус Христос»;
  - «С Адама»;
  - «С Иисуса Христа»;
  - «Родословие Иисуса Христа (Мф 1, Лк 3)»;
  - «Ключевые лица»;
  - «Всё небо»;
  - «Рассказ: от Адама до Иисуса Христа» — шаги рассказа со стихами.
- **Лицо, найденное поиском** или открытое в указателе, встаёт на карту закреплённым.
- **Следы жизни** на пошаговой карте выключены по умолчанию и включаются флажком.

### А.3. Небо — всё небо и общие правила

- **Знаки.** Мужчина — диск; женщина — диск в кольце; народ из Быт 10 — пунктирный кружок; Иисус Христос — единственная восьмилучевая звезда; царь — черта над знаком; роль — сокращение после имени («ц.», «пр.», «суд.», «ап.», «праот.» — у всех праотцев одинаково).
- **Связи.** Родитель → ребёнок — прямые отрезки: вертикальный ствол от следа родителя, зубцы к детям. Дети собраны по матерям. Ромб союза стоит на следе матери. Никакого «спагетти»: связи не пересекают имена; длинная связь — двумя обрывками с указанием цели.
- **Выбор лица** подсвечивает весь его род: предки — сплошные линии, потомки — штрих, цвет — по союзам (матерям). Остальное гаснет до 25 %.
- **Масштабы** по мере увеличения:
  1. облака плотности, эпохи, созвездия, ленты;
  2. яркие звёзды;
  3. все звёзды, следы и связи;
  4. даты и роли.

  Переходы плавные. Подписи не мигают: пороги их видимости вычислены заранее.
- **Ось времени:**
  - по умолчанию — «По эпохам»: время растянуто там, где много лиц, растяжение не больше 1 : 6;
  - линейка сверху называет эпохи; масштабная линейка — местная, «≈ N лет»;
  - точный или расчётный год — в карточке;
  - второй режим — «Равномерный по годам» с линейкой лет;
  - переход между режимами плавный, выбранное лицо остаётся в центре.
- **Меридианы ключевых событий:** Потоп, призвание Аврама, Исход, закладка храма, плен, возвращение, Рождество.
- **На широком экране карточки поверх неба нет:** карточка лица, союза или связи открывается справа. На телефоне карточка — нижний лист с тремя положениями: шапка 104 px, 55 %, 100 %.
- **Органы неба** (строка показа, кнопки масштаба, вступление) не закрывают лиц карты. Если закрывают на первом экране, небо сдвигается.

### А.4. Линии Мессии

- **Источник линий** — только явные последовательности `data/lines/joseph.json` и `data/lines/mary.json`, шаг за шагом по Мф 1:2–16 и Лк 3:23–38, у каждого шага — стих и номер.
- **Линия Иосифа:**

- **Расхождения:**
  - у Арфаксада на одно поколение: Каинан (Лк 3:36), которого нет в основном тексте Быт 11:12. Это два прочтения одного родословия, а не два ребёнка одного союза;
  - ниже Давида: Соломон и Нафан;
  - схождение у Салафиила и Зоровавеля;
  - расхождение через Авиуда и Рисая;
  - схождение в Иисусе.

### А.5. Карточка лица — 24 раздела

**Шапка:** имя, уточнение, паспорт таблицей (роль, созвездие, колено или народ, годы, эпоха, линии Мессии с номером у Матфея и Луки) и мини-шкала жизни на фоне эпохи.

**Разделы:**

| Часть | Разделы |
|---|---|
| I. Личность | 1 Имя; 2 Имя в подлиннике; 3 Значение имени; 4 Другие имена; 5 Роль и положение |
| II. Происхождение | 6 Родители; 7 Род, колено, народ; 8 Рождение |
| III. Семья | 9 Супруги; 10 Дети по матерям; 11 Братья и сёстры; 12 Иное родство |
| IV. Время | 13 Эпоха и относительная хронология («после…, до…, при жизни…»); 14 Современники |
| V. Жизнь | 15 Места; 16 Занятие и служение; 17 Жизнеописание; 18 Слова; 19 Перед Богом; 20 Смерть и погребение |
| VI. Наследие | 21 В родословии Мессии; 22 Упоминания в других книгах; 23 Места Писания (полоса 66 книг); 24 Примечания |

**Правила карточки:**
- **Три состояния раздела:** «есть сведения», «в Писании не сообщается» (проверено), «не составлен» (бледнее). Соседние пустые разделы сливаются в одну строку.
- **Каждый факт живёт в одном разделе**, остальные ссылаются на него («см. 8»).
- **Ссылка на стих** раскрывается вклейкой под абзацем: до 3 стихов, дальше — «ещё N стихов».
- **Длинный раздел** показывает до 8 строк, дальше — «ещё N».
- **Карточка читается по строкам, а не пятном текста:**
  - подписи полей — гротеском;
  - записи разделены отбивкой и висячим отступом;
  - ссылки тише текста и не начинают строку;
  - «Родство» — под шапкой таблицей, дети по матерям, у каждой матери цвет её ветви на небе.

### А.6. Инструменты исследования

- **Поиск:**
  - по имени, иным формам, подлиннику, уточнению и стиху («Руф 4:21» → все лица стиха);
  - раскладка исправляется сама («lfdbl» → «давид»), ё и е не различаются, окончания отбрасываются;
  - в строке результата — имя, уточнение, роли, эпоха и микрошкала жизни.
- **Указатель:**
  - алфавитный каталог;
  - «Вся Библия | Ветхий Завет | Новый Завет» — по книге, где лицо названо впервые;
  - выбор книги — все лица, названные в ней (имя или его падеж, а не прилагательное: «поля Моавитские» — не Моав);
  - заглавия книг — синодальные, в предложном падеже («в Послании к Евреям»).
- **Родство двух лиц:**
  - все пути длиной до кратчайшего + 2, с названием степени («Руфь — прабабушка Давида»), синодальным термином и пометой «по толкованию»;
  - путь рисуется на небе;
  - дальние — «общий предок — Иуда; 12 поколений вверх, 9 вниз».
- **Сквозной раздел:** один раздел карточки по группе лиц (цари Иудеи, судьи, линия Иосифа).
- **Разворот:** две карточки рядом, цепочка родства между ними.
- **Чтение главы:** Быт 5, 10, 11, 36; 1 Пар 1–9; Руф 4; Мф 1; Лк 3 — текст, где каждое имя — ссылка, а лица главы подсвечены на небе.
- **Эпохи:** ярусы (эпохи, судьи, цари Иудеи и Израиля с синхронизмами текста, служения пророков, события). Столбец жизни выбранного лица проходит через все ярусы.
- **Хронологические модели** (переключаемые, разница показывается):
  - по умолчанию — масоретские числа, 430 лет в Египте, якорь 967 г. до Р. Х.;
  - краткое пребывание — 215 лет;
  - числа греческого перевода из скобок;
  - Фарре 70 лет.

  Все годы, зависящие от модели, помечены «расч.» с названием модели.
- **Слой хронологических напряжений** — со стихами и объяснением.
- **Карта мест (география):**
  - места лица и главы на карте, с точками и маршрутами странствий, где текст их называет;
  - у каждой точки стих;
  - координаты помечены «справочно» и снабжены источником;
  - карта связана с небом и карточкой.
- **Глубокие ссылки** хранят лицо, окно, показ и шаги карты.

**А.7.4. Проверка на шаблонность — на каждом экране:**
- нет кремового фона и терракотового акцента;

- нет подписей прописными над заголовками (прописные разрядкой — только названия созвездий);
- нет строк «А · Б · В» и подписей «СЛОВО — фрагмент»;
- нет моноширинных подписей данных;
- нет стрелок «→» у кнопок;
- нет нумерации «01 / 02» (кроме 24 разделов);
- нет «пилюль», тостов, мерцающих скелетов, стоковых иконок, эмодзи.
