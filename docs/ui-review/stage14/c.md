## Отчёт эксперта C (этап 14): столкновения, подписи, z-order

**Инструмент.** Скрипт `tools/_c-collide.ts` работает на сборке `.ui-build/base14`, порт 4802.
- Запуск: `npx tsx tools/_c-collide.ts` (42 сцены, около 8 минут). Ключи: `--scenes a,b`, `--shots`, `--dump`.
- Результат: `.ui-shots/c/collide.json` и `collide.md` (таблица по сценам плюс до пяти примеров на класс).
- Помощники: `tools/_c-agg.ts "<класс>" [сцена]` выводит находки по классу, `tools/_c-crop.ts '<адрес>' имя x,y,w,h` снимает вырезки ×2.

Как он мерит. До загрузки страницы ставятся обёртки на методы `CanvasRenderingContext2D` холста `.sky`. Записывается каждый кадр: пути со stroke/fill, текст с настоящими метриками `measureText().actualBoundingBox*`, `fillRect` (гашения), clip, save/restore, преобразования. Поэтому замер не зависит от модели границ атласа (`Placer`/`textBox`). Что из этого извлекается:
- знаки — блок `drawGlyph` (подложка цвета неба на месте звезды из `data-stars-at`); видимые части: диск, кольцо, точки народа, черта царя, звезда Мессии;
- ромбы — из `data-links`, засчитываются только реально залитые;
- подписи лиц — по `data-label-boxes`;
- линии — по цвету: `sel` (жёлтая связь), `ribbon`, `kin` (золотистые дуги), `ring`, `map` (сетка, контуры, меридианы), `trail` (след), `link` (совпадает с путём `data-links`), `line` (прочее). Учтены гашения после линии и вырезы clip;
- HTML поверх холста.

Пути связей в браузере доступны через `data-links`, перепись не понадобилась.

### 1. Что работает и что сохранить
- **Подпись на подпись не ложится.** По глифам — 0 пар во всех 42 сценах, `Placer` сообщает то же (`data-labels` …/0; одно наложение в judah-group). Единая проверка всех видов подписей себя оправдала.
- **Границы подписей точны.** Ширины берутся из `measureText`. Ни один глиф не вышел за прямоугольник `Placer` (вылет 0).
- Подписи не срезаются кромкой неба, «подписей без звезды» нет.
- **Вырезы под жёлтой связью.** Clip evenodd по прямоугольникам подписей (marks.ts:1222–1229) — правильная техника. Её надо распространить на все слои (см. C1, C7).
- Свой след гасится под подписью (`knockTrail`), у текста ореол 1,5 px.
- **Карточка у звезды на 1440** не закрывает ни одного имени семьи (зоны обязательные/желательные работают).
- **Телефон.** Лист не перекрывает небо: холст укорачивается, звёзд под листом 0.

### 3. Система вместо заплаток

**Фактический порядок слоёв** (sky.ts:1580–1803):
небо → полосы эпох → метки времени → черты событий → сетка → облака → контуры созвездий → скопления → следы → полосы рождения → связи → ленты (свечение, нити) → разрывы «+N» → следы лиц линий → путь родства → ◆ • → звёзды → **подписи** (выбранное, Иисус, «+N», отметки, семья, по порогам; между ними пометы, обрывки, названия) → † → метки ветвей → **кольца, дуги родства, призраки** → **жёлтая связь** → ярусы эпох → рамка → меридиан → указатели у края → HTML (строка показа, органы, карточка, подсказка).

**Целевой порядок:**
фон → декор (с разрывами под текстом) → облака → погашенные следы и связи → ленты → активные связи семьи → ◆ • → звёзды → кольца состояний → дуги и призраки (с разрывами) → выбранная связь (вырезы под всеми подписями) → **весь текст** → рамка и указатели → HTML-резерв.

1. **Двухфазный кадр.** Сначала раскладка без рисования: знаки, узлы, пути связей (`LinkFrame`), кэш лент, маршруты дуг и призраков, кольца, оверлеи. Всё это известно до рисования. Затем рисование слоёв с вырезами по прямоугольникам глифов. Затем текст. Подготовка: `labelStar` и `claim` возвращают команду рисования, а не рисуют сразу.
2. **Модель границ.** В `Placer` попадают истинные фигуры:
   - знак (диск, кольцо, точки народа, звезда Мессии, черта, †) — жёсткий;
   - кольца состояний (с owner) — жёсткие;
   - ◆ и «+N» — жёсткие;
   - в сетку отрезков `LinkHits` добавляются ленты с полем свечения, дуги, призраки и путь выбранной связи — с весом важности;
   - следы и декор остаются в `p.lines`, со стоимостью и разрывом;
   - оверлеи (карточки, подсказка) входят в резерв.
3. **Правила кандидата.** 4 стороны и 4 угла, затем выноска не длиннее 40 px. Кандидат отбрасывается, если:
   - пересекает жёсткое;
   - через середину строки идёт связь или лента не своего лица;
   - нарушена принадлежность: в полосе строки на 0,6 кегля слева и справа есть чужой знак; чужой знак ближе своего на 3 px и больше; выноска пересекает выноски или линии семьи; у конца выноски чужой знак ближе своего;
   - подписи на одной строке стоят ближе 0,5 кегля друг к другу.

   Среди допустимых побеждает наименьшая стоимость: длина следов и декора под строкой плюс отход от прежней стороны (гистерезис стороны). Если допустимых нет — подпись скрывается и попадает в список «скрытых»: она появляется при наведении, фокусе или выборе, диктор её читает.
4. **Приоритеты:** выбранное (звезда, кольцо, имя) → концы и роли выбранной связи → путь связи и связи семьи → ◆ → имена семьи → Иисус → прочие по степени интереса → названия созвездий → декор.
5. **Раскрытие по масштабу:**
   - обзор: величины 0–1, выбранное, названия созвездий; пересекающиеся знаки — «скопление +N»;
   - эпоха: пороги из сборки;
   - семья (строка от 14 px): все, кому нашлось допустимое место; при нехватке — команда «Раскрыть семью» (укладка Г).
6. **Скорость.** Резерв колец и проверка по сетке отрезков дают +1 запрос на кандидата, около +0,3 мс на 200 подписей. Вырезы — один клип на 2–3 слоя, около 0,3–0,6 мс. Скопления семьи — O(n) по сетке. Пороги переходят в сборку, из кадра уходит пересчёт `LabelCache` при смене размера. Бюджет 16 мс при 5 000 лиц сохраняется. Риск один — перестройка порядка в `sky.ts`.
