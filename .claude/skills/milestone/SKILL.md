# После вехи (координатор)

Веха — решение владельца, принятая рецензия, новая редакция документа, этап данных, исследование, прототип, новое правило или инструмент.

1. Решение владельца сначала — в `docs/app/00-РЕГЛАМЕНТ.md` как `**В-N (дата). Название.**` (номера подряд) со строками «Состояние: действует» и «Затрагивает: …»; заменённым прежним решениям — «Состояние: заменено…: В-N». В `docs/app/ВОПРОСЫ.md` вопрос получает состояние `ответ: В-N`. Новые вопросы владельцу — новой строкой ВП-N в реестр.
2. Проверка вехи (В-20): агент `milestone-checker` по `docs/app/ПРОВЕРКА-ВЕХИ.md`. Если заняты четыре места — в журнале «Проверка вехи: отложена», агент проверяет, когда место освободится. Самопроверка — только для вех без изменения документов.
3. Строка в `docs/app/ЖУРНАЛ.md` под сегодняшней датой, сверху: `- ЧЧ:ММ (`хеш`) — что произошло. Где: путь. Что дальше. Проверка вехи: … | отложена.` Время — `date -u +%H:%M`, не на глаз.
4. «Сейчас» в `docs/app/КАРТА.md` (выше маркера): 3–5 строк — фокус и решения координатора, штамп `*Обновлено: ГГГГ-ММ-ДД ЧЧ:ММ.*` по `date -u`. Что ждёт владельца и долги карта собирает сама — руками их не писать.
5. `npm run -s map`, затем `npm run -s docs:check` — ноль ошибок. Хук перед `git commit` повторяет это сам и не пропустит коммит с ошибками.
6. Закоммитьте карту, указатель и журнал вместе с работой; запушьте.

Не больше четырёх агентов одновременно (обязательное решение владельца, регламент § 9).
