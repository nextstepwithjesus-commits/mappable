# 03. Общая база, идентичность и соответствие стихов

Статус: концептуальный контракт v0.3, не реализованная схема БД. Технология хранения выбирается после проверки запросов и объёма.

## Сущности

| Сущность | Содержание | Ключевое ограничение |
|---|---|---|
| Referent / Actor | Установленный индивидуальный участник или иной референт, варианты именования | Один постоянный ID; имя не является ID, Бог не тип creature |
| PersonProfile / ActorType | Человеческие сведения либо иной засвидетельствованный тип | Человеческие родители/возраст не навязываются духовным существам и образам |
| Collective / Category | Группа с составом/численностью либо справочный вид | Коллектив не отдельный человек; вид не индивидуальное животное |
| Mention / RepresentationContext | Адресное упоминание и повествование/видение/притча/речь | Кандидатное тождество не увеличивает число установленных участников |
| GroupScheme / GroupEnumerationEntry | Контекстный перечень, его порядок и адресные позиции | Число12 не универсальная taxonomy; человек/коллектив/упоминание раздельны |
| MembershipAssertion | Принадлежность дому, народу, группе или списку | Не создаёт ребро непосредственного отцовства |
| FamilyContext | Подтверждённый союз либо контекст происхождения | Контекст происхождения не утверждает супружество |
| ParentageAssertion | Родитель, ребёнок, вид происхождения и основание | Биологическое, предок, законное, текстовое перечисление и толкование не смешиваются |
| KinshipAssertion | Супруги, братья/сёстры и прочее родство | Прямое братство возможно без известных родителей |
| MissingParentSlot | Недостающее сведение о родителе конкретного ребёнка | Имеет пояснительную карточку, но не входит в счётчик лиц |
| Event | Описанное событие с участниками и ролями | Не равно любой совместной встречаемости имён |
| EventAccount / EventIdentityAssertion | Адресное описание и проверяемое сопоставление описаний эпизода | Пересказ не новое событие автоматически; различия оснований сохранены |
| ParticipationAssertion / EventPlaceAssertion | Участник/роль/фаза и текстовое место/роль | Упоминание не участие; место не точная современная координата |
| EventRelation | Части эпизода, порядок и иные принятые отношения событий | Порядок текста не автоматически хронология или причинность |
| InteractionAssertion | Направленное/взаимное отношение участников | Привязка к событию/стиху и смыслу обязательна |
| Place / NameAttestation | Древнее место и его наименование в тексте | Отдельно от современной геометрии |
| LocationCandidate / GeometryAssertion | Возможная идентификация и геометрия | Период, точность, аргумент и права независимы |
| LifeStateEvent / ParticipationContext | Смерть, возвращение к жизни, явление и текстовый контекст участия | Поздний эпизод не исключается автоматически первой смертью |
| TemporalAssertion / Model / Placement | Исходное временное сведение и расчёт | Версия модели не меняет исходный стих |
| Verse / Passage / TextFragment | Текст конкретной версии, канонический статус фрагмента | Ссылка не означает весь стих поддерживает утверждение |
| Source / Assertion / Review / Coverage | Происхождение, утверждение, проверка и охват | «Проверено» имеет указанный субъект/метод/область |

ID непрозрачный, устойчивый, с пространством имён типа `actor`, `collective`, `place`, `event`, `assertion`, `slot`. Одного «номера» достаточно для одной сущности во всём приложении; тип исключает столкновение места и человека. Старый ID хранится как alias/redirect в таблице миграции. ID не меняется из-за названия инструмента, порядка, нового имени или дополнительного источника.

Слияние участников/мест/событий — редакционное решение с доказательствами, обратимым журналом и перенаправлением старых ссылок. Одинаковое написание, общая транслитерация или совпадение координат не доказывают тождество. Расщепление ошибочно объединённой записи сохраняет связь с исходной версией и повторно проверяет зависимые отношения.

Событийная рабочая область — [документ15](15-events-workspace.md). Один EventID может иметь несколько свидетельств и несколько геометрических отметок; distinct событие, число отметок и уровень детализации не смешиваются. ParticipationAssertion означает принятую роль в действии/фазе, просто упомянутое лицо связано через Mention/EventAccount. Общий эпизод не доказывает встречу; состав альтернативных сценариев не объединяется в одну фактическую сцену. Страница события имеет собственные EV-ID, порядок PC разделов участников сохраняется.

Для колен и родов принадлежность, представительство/роль и присутствие в источниковом перечне различаются по типу отношения. Поля основания (прямое/вычисленное) и разрешённости (установлено/неоднозначно) независимы. Родоначальник, коллектив колена, поколение и территория имеют отдельные ID. Вычисленное происхождение не автоматически членство во всех контекстах; правила/входы проверяются адресно. [Спецификация колен](14-tribes-and-area-navigation.md).

Классификация имеет независимые оси: вид записи (индивидуальная/коллектив/категория), характеристика референта и контекст отдельного упоминания. «Животное в видении» нельзя автоматически сделать зоологическим участником истории. Божественные наименования и вопросы тождества требуют отдельной богословской редакции, без автоматического объединения по словарю. Индивидуализированное животное получает Actor ID и общую Карточку; человеческая генеалогия остаётся типизированной проекцией базы. Нерешённые упоминания сохраняются и доступны, но не выдаются за уже установленных разных существ.

## Атомарное утверждение

Обязательны: ID; субъект/предикат/объект; область применимости (ребёнок, событие, период, модель); исходные стихи/фрагменты; вид основания; допущения/входные утверждения; альтернативная группа; состояние проверки; составитель/проверяющий с типом human/agent; версия/история. В справочном утверждении — внешний источник и права. У прямого библейского факта — принятый Синодальный фрагмент.

Основание и уверенность разделены. «Вывод» может быть строгим в рамках допущений; «публикация» может предлагать спорную координату. Одно поле `cert` не описывает всё. Для долей/процентов требуется объявленная методика; вместо неподтверждённых процентов используются точные словесные статусы.

Каждый ребёнок принадлежит контексту на основании своих родительских утверждений. Присутствие женщины и нескольких детей в визуальном блоке не назначает её матерью всем. Если материнство неизвестно для двух детей, два служебных слота не доказывают ни одну общую мать, ни двух разных матерей. Их объединение требует нового основания.

Неназванная жена Каина в Быт 4:17 — засвидетельствованное лицо. Слот матери Еноса из сведений Быт 5:6–8 — обозначение отсутствия информации в указанной области чтения, а не установленная «жена Сифа». Слот имеет собственный пояснительный экран и связь с ребёнком; его нельзя экспортировать как установленного участника. Источник позже может установить лицо, тогда новая версия заменяет слот ссылкой, сохраняя историю.

Нулевые/отсутствующие поля различают: ещё не исследовано; не сообщено в проверенной области; противоречивые варианты; не применимо; подтверждённо отсутствует. «Не применимо» важно для происхождения Адама/Евы и особой истории Иисуса; общая автоматическая вставка двух биологических родителей запрещена. Область прочитанного отрицательного результата записывается явно.

### Проверка относится к ревизии

Review закреплён за неизменяемыми assertionRevision/contentHash, ревизиями опорных фрагментов/идентичности и значимыми версиями метода/модели. Семантическое изменение субъекта, отношения, источника или входов создаёт новую ревизию: прежний вердикт сохраняется в истории, но не автоматически утверждает новый смысл. Зависимые утверждения помечаются для повторной проверки по происхождению; новый выпуск не наследует их «принято» молча.

Механическая воспроизводимость расчёта по отдельно принятому алгоритму — отдельный тип Review и не замена чтению библейского утверждения. Неизменные данные после косметической UI-правки не требуют повторного полного чтения. Публикационные snapshots и старые подписи сохраняются; принятие относится к объявленным байтам/смыслу/области.

## Система стихов

Внутренний адрес включает `editionId + bookId + chapter + verse + fragment`, а версия текста — отдельный неизменяемый объект с контрольной суммой. Канонический охват 66 и система нумерации — разные свойства. Нельзя предположить, что любое внешнее «Synodal» совпадает с нашим цифровым файлом. Это различие отражено в документации [CrossWire alternate versification](https://wiki.crosswire.org/Alternate_Versification); готовая карта соответствия нашему корпусу этим документом не подтверждается.

Таблица соответствия хранит исходную систему/версию и **множество** целевых фрагментов с порядком, статусом exact/partial/ambiguous/no-canonical-counterpart, основанием, проверяющим и версией. Возможны один→несколько, несколько→один, разрыв и отсутствие соответствия. Автоматический сдвиг номера главы или стиха недопустим.

Конвейер: обнаружить внешнюю ссылку → определить точную версию/нумерацию → получить кандидаты → сравнить содержание и контекст с нашим основным текстом → отдельно исключить неканонические/скобочные части → независимо принять соответствие → принять либо отклонить утверждение. Неоднозначное соответствие отправляет строку в карантин, а не подставляет ближайший стих. Все принятые импортированные утверждения сохраняют исходный адрес вместе с Синодальным.

Будущая приёмка: весь импортированный охват имеет проверенную карту; граничные главы и варианты Псалмов/Даниила проверяются адресно; несоответствующий фрагмент не получает библейский статус; обратное соответствие возвращает набор, не обязательно один исходный номер. При отсутствии полного соответствия импортируется только явно принятый поднабор.

## Версии и общий поиск

Каждый выпуск объявляет версии корпуса, утверждений, соответствий, хронологических моделей и географических наборов. Один поисковый индекс строится из принятых сущностей/имён/ссылок; кандидаты доступны только в явно обозначенной исследовательской области. Служебные слоты ищутся из конкретного семейного контекста и не занимают место «нового библейского человека» в глобальных итогах.

Отсутствующие родственные отношения не выводятся из соседства в списке. Ограничение участия жизнью имеет явный контекст применимости. События смерти/воскресения и явления не сводятся к одному закрытому birth–death интервалу; последующие участия проверяются по тексту, а не удаляются как ошибки. Событие связывает участника со временем и местом; отображение одной версии не перезаписывает другие. Экспорт включает состояния неопределённости и ссылки, а не только красивую геометрию.

## Инварианты будущих проверок

Нет дубликатов ID/висячих ссылок; каждому принятому утверждению соответствует основание и версия; направленные биологические циклы разбираются как ошибка/неверный тип; альтернативы не складываются в одну цепь; ни один placeholder не увеличивает census лиц; факт отображается одинаково во всех инструментах; любой переход сохраняет идентичность. Структурная проверка не заменяет независимое чтение текста.
