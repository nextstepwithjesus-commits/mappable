# 11. Роли, независимая проверка и этапы

Статус пакета: **v0.7, спецификация и подготовка базы знаний нового приложения**. Владельцем приняты шесть основных разделов и прекращение разработки ToliDot. Документы не объявляют приложение или весь корпус готовыми. F1 начат; текущее поручение — углубить документацию, библиотеку историй и требования всех инструментов, без реализации. Новая работа локальная; только частичная база персонажей/утверждения/ссылки после новой проверки могут переноситься. Старые UI, дизайн, код, прикладная логика и механика не переносятся.

## Ответственность

| Роль | Отвечает за | Кто проверяет |
|---|---|---|
| Ведущий/редактор продукта | Границы инструментов, решения, интеграция документов, открытые вопросы | Независимые рецензенты и владелец по существенным решениям |
| Составитель библейских сведений | Адресные упоминания, утверждения, кандидаты идентичности | Отдельный сверщик читает те же стихи/контекст |
| Библейский редактор | Типы родства, богословские/текстовые различия, отрицательные сведения | Независимый редактор; спорные вопросы передаются профильному человеку |
| Хронолог | Допущения, ограничения, источники альтернатив, вычисления | Независимый воспроизводящий расчёт и проверка календарей |
| Географ/историк | Идентификации, периоды, геометрия, аргументы | Независимая проверка локализации и прав |
| Дизайнер/UX-исследователь | Задания, макеты, читаемость, дети/взрослые | Пользовательские испытания и специалист по доступности |
| Разработчик/инженер данных | Реализация принятого контракта, версии/индексы/переходы | Code review, смысловые и поведенческие проверки |
| Инженер производительности | Профиль узких мест, reference devices, бюджеты | Воспроизводящий измерения проверяющий |

Роли не означают нанятых людей или их квалификации. В этом шаге работают агенты-исследователи/рецензенты; человеческая библеистика, дизайн-испытания и научная экспертиза не считаются заменёнными.

## Экономная команда

Текущая модель по настройке владельца — Astra/ultra. Одновременно ведущий и до двух ограниченных исполнителей. Нет размножения задач без необходимости. Исследователь родства/источников и исследователь времени/географии владеют отдельными файлами; первый дополнительно выполнил адресное исследование всех акторов/областей. Затем два независимых критика проверяют другие документы, не собственные выводы.

Каждый бриф задаёт результат, источники, владельческие файлы и предел. Сначала используется уже прочитанное, затем адресно исследуется конкретный пробел. Противоречие не исправляется очередным одинаковым голосованием агентов. Нужен источник/метод/контрпример. Субагенты не правят общую память; ведущий принимает передачу и записывает решения.

Для текущего расширения ведущий отвечает за18/19 и интеграцию. Один агент исследует текстовую модель/источники, другой — читательские сценарии/UX; затем они независимо критикуют договоры ведущего и чужую область. Автор своей схемы не закрывает найденную другим критиком ошибку. Источниковый редактор применяет02 к христианским библейским/историческим работам; технические стандарты/HCI отвечают только за свои методы. Полный [стандарт19](19-quality-and-review-standard.md) задаёт карточку спецификации и приёмку каждого инструмента.

## Состояния и доказательства

Документ: черновик → независимо просмотрен → замечания исправлены/открыты → пригоден для объявленного следующего шага. Утверждение: кандидат → адресно проверено составителем → независимо принято либо отклонено/неоднозначно. «Получен отчёт» не равно «принят весь факт». Отрицательный результат имеет область чтения; отсутствие карточки в старой базе не доказывает отсутствие в Библии.

Для решения записываются вопрос, варианты, доказательства, выбранная гипотеза или прямое решение владельца, риск, критерий пересмотра и ответственный. Источник недоступен — чтение не заявляется. Частичная проверка и конкретные открытые вопросы публикуются рядом с результатом. Исторические красные проверки прежнего продукта сохраняются как свидетельства; они не превращают завершённую разработку ToliDot в активную задачу и не подменяют новые критерии приёмки. Старые результаты проверки данных могут учитываться только для неизменных ревизий и заявленного охвата.

## Этапы с условиями перехода

| Этап | Результат | Условие перехода |
|---|---|---|
| F0. Основа | Спецификации шести разделов и библиотеки историй, общая модель/источники, роли и открытые вопросы | Противоречия документов разобраны, карточка каждого инструмента по19 проверяема; источниковые пробелы не скрыты |
| F1. Канонический реестр | Протокол66, утверждения/упоминания/тождество, классификация историй/свидетельств, проверяемая миграция частичной базы | Выпущенный поднабор независимо принят; полнота только для закрытого охвата/версии политики; цифровые дефекты не замаскированы |
| F2. Сравнение интерфейсов | Новые аннотированные состояния и прототипы на небольшом принятом наборе; книга→история→участник→инструмент→источник→возврат | Семантическая/UX-критика, доступность и объявленный план испытания с людьми; выбор после задания/сравнения, не похвалы агента |
| F3. Сквозная основа приложения | Поиск, ID/Карточка, источники и переходы; один инструмент за раз | Работает сценарий пользователя, версии воспроизводимы, нет смешения кандидатов/фактов |
| F4. Принятые инструменты | Проверенные инструментальные проекции и управление по результатам F2 | Семантика, UX/доступность и performance проверены раздельно на объявленном объёме |
| F5. Полный канон/выпуск | Все акторы и обязательные утверждения принятого охвата, лицензии/документация/обновления | Все обязательные очереди закрыты, права соблюдены, реальное пользовательское исследование/проверки завершены |

F1 и исследование F2 можно вести по отдельным принятым небольшим наборам; это не разрешение назвать весь канон проверенным. Полная миграция не нужна для сравнения двух механик, но демонстрационные примеры должны быть верными. Сначала фундамент каждой идеи, затем её реализация. Существенные изменения цели обсуждаются с владельцем; каждое косметическое решение не требует повторной остановки.

## Проверка каждого инструмента

Четыре независимые оси: данные/источники; понимание задачи; доступность/устойчивое управление; скорость/ресурс. Проход одной не компенсирует провал другой. Минимальный контрольный набор содержит колено Рувима/четыре поколения/непривязанную цепочку и контекстные перечни; три семьи, родство супругов, неизвестную мать, повторного предка, отдельную компоненту, тёзок разных типов, краткую карточку, коллектив, неопределённую дату, неизвестную остановку и событийную связь.

Порог/метод объявляются до опыта. Нельзя ослаблять их после отказа или повторять зелёные проверки без нового риска. Ошибка интерфейса исправляется в интерфейсе; источник не меняется ради удобной геометрии. До утверждения численной модели хронологические значения не становятся production facts.

Библиотечная матрица добавляет большой цикл/короткую историю, разные рассказы/поздний пересказ/упоминание, межзаветный фильтр, ненарративные фрагменты/повествование внутри поэзии, неучастника в речи и спорное тождество. Полный указатель не заменяется популярной подборкой. Любая известная подтверждённая неисправленная ошибка блокирует выпуск; приоритет определяет очередь ремонта, а не разрешение ошибки. Обозначенная нерешённая интерпретация не дефект сама по себе.
